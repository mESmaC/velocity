- **command**
  - `watch_rosen_status { project_identifier }`

Starts the selected project's Rosen status subscription and cancels the previous one.
A null identifier stops the subscription when no project is selected.
The command returns whether the selected project uses Rosen.

- **command**
  - `get_fleet_stats { project_identifier }`

Returns the project's fleet development ledger summary for the last 24 hours and the last 7 days, including land counts, median filed-to-landed and dispatched-to-landed times, idle slot-minutes, tokens per landed change, post-land failure and revert rates, check queue median wait, retries per issue, review findings, and top offenders (slowest issues, most tokens, most retries) with issue and thread links (#619).

- **command**
  - `switch_to_after_land { project_identifier }`

Proposes the one-line `review = "after-land"` edit in `rosen.toml` for a `before-land` Rosen project, records the owner's approval, runs any configured pre-land checks on the staged land result, submits the receipt and lands the change (#524).
After landing, it wakes the landing runner so subsequent clean named changes land automatically.

- **command**
  - `run_rosen_thread_action { project_identifier, thread_identifier, change, action }`

Validates the owning thread and its current Rosen change before running Name with a message, Rebase, Abandon or Resolve.
Workspace mutations run at an agent turn boundary.
Resolve saves a conflict handoff for the agent, recreates a missing workspace when possible, delivers immediately when the thread is idle or its session has ended, and otherwise records the pending or blocked status on the change view (#522).
Background Rosen follow-up delivery errors surface on the thread's change view.
The change track, land history and sidebar stage arrive in the existing layout snapshot.

- **command**
  - `cut_release { project_identifier, version, commit }`

Releases `commit`, or Rosen's last green commit when it is null, as `v<version>`.
For projects mirrored to Collapse, Rust validates the green commit locally, verifies the Tauri updater signing key in Windows Credential Manager, uses a saved Collapse release token or creates one from the signed-in Collapse session (`velocity-releases-<machine>`, `releases` scope, replacing it once on 401/403), runs the signed `scripts/release-local.ps1` build (including the Linux `velocity-graph` archive on Velocity), publishes the release and assets to Collapse, and rewrites `latest.json` on Collapse's rolling `updater` release (#593, #607).
For GitHub-only projects without a Collapse mirror, Rust dispatches `release.yml` on GitHub as before (#431, #521).

- **command**
  - `get_release_credentials_status`

Reports whether the Tauri updater signing key (`velocity:updater-signing-key`) and Collapse releases personal access token (`velocity:collapse.sh:releases`) are stored in Windows Credential Manager, including whether the release token was pasted or created from Collapse sign-in and its creation timestamp, without exposing any secret values (#593, #607).

- **command**
  - `set_updater_signing_key { private_key, password }`

Saves or replaces the Tauri updater signing private key and optional password in Windows Credential Manager (`velocity:updater-signing-key`) and returns the updated credential status (#593).

- **command**
  - `clear_updater_signing_key`

Removes the Tauri updater signing key from Windows Credential Manager and returns the updated credential status (#593).

- **command**
  - `set_collapse_release_token { token }`

Saves or replaces a manually pasted Collapse personal access token with the `releases` scope in Windows Credential Manager (`velocity:collapse.sh:releases`) so it takes precedence over sign-in-created tokens, and returns the updated credential status (#593, #607).

- **command**
  - `replace_collapse_release_token`

Mints a fresh Collapse personal access token with the `releases` scope (`velocity-releases-<machine>`) from the signed-in Collapse session, stores it in Windows Credential Manager (`velocity:collapse.sh:releases`), records `"Created a Collapse release token from the signed-in session"` in diagnostics without logging the secret, and returns the updated credential status (#607).

- **command**
  - `clear_collapse_release_token`

Removes the Collapse releases token from Windows Credential Manager and returns the updated credential status (#593).

- **event**
  - `rosen://status`

Publishes an initial status snapshot and updates from Rosen for the selected project, including owning thread links and reconnect errors.
The UI filters incoming snapshots by project identifier.

- **event**
  - `collapse://link`

Emitted when a `velocity://collapse/<owner>/<name>` or `velocity://collapse/<owner>/<name>/land/<commit>` deep link arrives (#479).
Rust parses the URL, ignores unknown paths and query parameters, and never passes link text into a prompt or a shell.
When a local project's Collapse mirror matches `<owner>/<name>`, Rust focuses that project, opens an unsent draft thread with optional `"Land <short commit>"` context, and emits the matched outcome so the window focuses the draft composer.
When no local project matches, Rust checks Collapse's dashboard (#575): an unlinked repository opens through the same Open from Collapse path (F2), while a repository that already has a linked server emits a machine-enrollment notice offering Settings (`Settings → Workspaces → Machines`), and an inaccessible or disconnected repository emits an unmatched notice.
