- **command**
  - `get_issue_panel`,
  - `open_project_issue { project_identifier, number }`,
  - `dispatch_issue { project_identifier, number, accept_recommendation }`,
  - `toggle_issue_expanded { number }`

Active-project open issue inventory for Work, the palette and the legacy issue rail (F9).
Legacy rail rows start collapsed; `toggle_issue_expanded` expands or collapses one row and the expanded set lives in the issue snapshot.
Native refresh reads open issues, labels, scout attribution and spec-question recommendations.
Opening an assigned issue selects its thread; otherwise it opens GitHub.
The AIRC modal's `#n` links open through the same command.
Dispatch re-reads the issue, checks the saved spec lock and atomically records issue ownership before starting the ordinary worktree/ACP lifecycle.
Accept scopes that thread to the recommended one-line proposed SPEC.md answer.

- **command**
  - `dispatch_work_issue { project_identifier, repository, number, accept_recommendation }`
  - `get_issue_discussion { project_identifier, repository, number }`
  - `open_issue_discussion { repository, number }`
  - `release_issue_hold { project_identifier, repository, number }`
  - `set_work_issue_expanded { project_identifier, repository, number, expanded }`

Work dispatch and Accept retain the repository-qualified identity of the selected row and use the ordinary single-issue launch path.
`release_issue_hold` removes `hold` and any retired hold labels from the issue, strips Velocity's person-hold block, posts a release comment and refreshes the Work view snapshot (#526).
Expanded rows load the issue opening paragraph and latest attributed agent comments through a separate GitHub request.
The GitHub discussion link opens the repository-qualified issue directly.
Work saves expansion in the project and publishes it through `layout://state`.

- **event**
  - `issue://panel`

Ordered active-project issue snapshots, refreshed natively on project selection and every 30 seconds, with owning-thread state updated from saved changes.
Failed refreshes retain the previous rows with the error.
A refresh reads the open-issue count and the most recently updated open issue, and reads the open issues in full only when either moved, and at least every 10 minutes; the project's GitHub client is kept between refreshes.
