#### §3.1 · F5 IPC

- **command** `get_machines { project_identifier }`

Read the authoritative Rosen roster, listener and recent dispatch results for F5 headless machines.

- **command** `enable_machine_listener { project_identifier, address }`

Configure the per-project Rosen TLS listener, persisting its bind address across restarts.

- **command** `create_machine_join_key { project_identifier, address, expires_in_seconds, uses, role }`

Create a fingerprint-pinned Rosen join key with an advertised address, expiry, use limit and agent/checker role.

- **command** `approve_machine { project_identifier, machine }`

Activate a pending Rosen machine with one click.

- **command** `revoke_machine { project_identifier, machine }`

Invalidate the machine's shared Rosen/dispatch credential and unregister it from dispatch.

- **command** `dispatch_to_machine { project_identifier, machine, prompt }`

Durably queue a prompt on an active registered machine after checking the project's locked spec.
No frontend shell command is accepted.

- **command** `get_workspace_settings`

Read the saved location and agent setup preferences and available drives.

- **command** `set_workspace_settings { edit, project_identifier }`

Persist a workspace preference edit.

- **command** `preview_workspace_folder { folder }`

Preview the workspace path while the user types a folder.

- **command** `browse_workspace_folder`

Select a location through the native folder picker.

- **command** `list_workspaces { project_identifier }`

List the project's Rosen registrations on this machine with the owning thread, measured size and change state.

- **command** `delete_workspace { project_identifier, change, path }`

Delete the selected registration through Rosen's guard and report any refusal.

- **command** `get_workspace_preparation { project_identifier }`

Read the effective warm pool size and prepare commands from Rosen's landed configuration.

- **command** `propose_workspace_preparation { project_identifier, expected, edited }`

Create and name a Rosen change to `rosen.toml` after checking the edit against its starting settings.

- **command** `open_collapse_page { url }`

Open a validated `https://collapse.sh/` or `https://github.com/` settings or setup page in the default browser (#611).
Reject any other host or scheme.

- **command** `open_on_collapse { project_identifier, commit }`

Open the project's Collapse repository page, or with `commit` that land's commit page, in the default browser.
Rust builds the address from the project's Collapse mirror and refuses a project without one.

- **command** `mirror_to_collapse { project_identifier, deleted_action }`

Make Collapse the project's mirror (#427): create the Collapse repository named after the project, hand its push token to git's credential helper, and land a `rosen.toml` change setting `[mirror] remote` and the `collapse` root (#517).
When the target name is held by a deleted Collapse repository pending purge (#610, collapse.sh#217), return `deleted_repository` with its deadline, settings link and recovery options (`restore` or `purge_and_create`) instead of reporting not found.
Allow the server's relay to run the actions Collapse offers.
For a GitHub project, call Collapse's downstream API (`POST /api/downstream/{owner}/{name}` with `{"github_repository": "<owner/repo>"}` only, reading state back with `GET /api/downstream/{owner}/{name}`, C4) right after provisioning; if the downstream cannot be set, show `GitHub copy is not being updated: <reason>` in the title bar and project health with a link to `https://collapse.sh/<owner>/<name>/settings` until Collapse reports in sync (#579, #611).
Leave forwarding alone when the project has no GitHub repository.
Report the outcome as a toast and return `MirrorToCollapseResult`, and refuse a project that is not on Rosen, already mirrors to Collapse or has no Collapse connection.

- **command** `send_collapse_live_state { project_identifier }`

Send Collapse the live state of a project that already mirrors there (#517): store the mirror's push token under the state feed and ledger URLs, land a `rosen.toml` change setting only the `collapse` root, and allow the server's relay.
Report the outcome as a toast, and refuse a project that is not on Rosen, has no Collapse mirror, or has neither a push token in git's credential helper nor a Collapse connection to mint one.

- **command** `get_project_collapse_settings { project_identifier }`

Read the project's landed `collapse` root, `collapse_channel` flag, push token status, state feed and ledger push health, Collapse relay allow-list, issue host, stored Collapse issues token status, configured GitHub/downstream repositories, and post-switch one-way GitHub issue sync status (#576, #589, #592, #612).
Returns `None` for non-Rosen projects.

- **command** `import_collapse_issues { project_identifier }`

Run the same GitHub issue import step Move to Collapse uses for a Collapse-hosted project whose issues were never imported, clearing the `Issues on Collapse were never imported from GitHub` warning and enabling post-switch one-way GitHub issue sync on success (#612).

- **command** `reimport_collapse_issues { request }`

Explicitly run Collapse's GitHub issue import again for a project whose import already finished, accepting optional GitHub repository and transient token overrides from the Move to Collapse form (#615).
Shown as a separate "Import again" action with a warning that it can overwrite Collapse issues from GitHub.

- **command** `move_to_collapse { request }`

Run the one-step GitHub-to-Collapse cut-over for a Rosen project (#592, #612, #615): check Collapse's import status (`GET /api/repositories/{owner}/{name}/issues/import`) and skip Step 1 as already done when the import has already finished so re-running Move to Collapse never overwrites or reopens Collapse issues; otherwise import GitHub issues into Collapse (`POST/GET /api/repositories/{owner}/{name}/issues/import`, collapse.sh#193) and wait until caught up, stopping before switching the mirror unless the import step Passed (a skipped or failed import stops the cut-over unless GitHub positively reports zero open and closed issues), link an existing Collapse repository (fast-forwarding it from Rosen's base) or create a new one, switch `[mirror] remote` and `collapse` root in `rosen.toml`, enable explicit Issues on Collapse (#589, #612), CI from Rosen (#591) and post-switch one-way GitHub issue sync (#612, #614), keep or remove the GitHub downstream mirror (`POST/GET /api/downstream/{owner}/{name}`, C4, #611), and run `rosen collapse check`.
When keeping GitHub fails to set the downstream, mark the downstream step Failed and surface `GitHub copy is not being updated: <reason>` in the title bar and project health with a link to `https://collapse.sh/<owner>/<name>/settings` (#611).
When the target Collapse name is held by a deleted copy pending purge (#610, collapse.sh#217), return `deleted_repository` so the caller can re-run with `deleted_action` set to `restore` or `purge_and_create` and report which action ran in the mirror step result.
Returns each step's result, the full `rosen collapse check` report, and the refreshed Collapse settings; safe to re-run.

- **command** `set_github_issue_sync { project_identifier, enabled }`

Turn the post-import one-way sync of GitHub issues opened or changed since Collapse's import `finished_at` on or off for a project (running until turned off) and return the updated Collapse settings (#612, #614).

- **command** `sync_github_issues_now { project_identifier }`

Run one immediate pass of the post-import one-way GitHub-to-Collapse issue sync and return the updated Collapse settings (#612, #614).

- **command** `set_collapse_channel { project_identifier, enabled }`

Propose and land a `rosen.toml` change setting or removing `collapse_channel` so Rosen sends or stops sending channel lines to Collapse (#576).
Returns the updated Collapse settings and a status message, and reports a toast.

- **command** `set_collapse_relay { project_identifier, allow }`

Save the project's allowed Collapse relay action kinds in persisted state and apply them to the project's Rosen server immediately (#576).
Returns the updated Collapse settings.

- **command** `unlink_collapse { project_identifier }`

Propose and land a `rosen.toml` change removing the `collapse` root (and `collapse_channel`) while keeping `[mirror] remote`, clear the server's relay allow-list, refresh mirror state and return the updated Collapse settings (#576).

- **command** `get_project_deploy_settings { project_identifier }`

Read the project's landed `rosen.toml` `[deploy]` steps and report whether each named secret is stored in Windows Credential Manager under `velocity/deploy/<project>/<NAME>` or satisfied by a signed-in local CLI login (`flyctl` for `FLY_API_TOKEN`, `wrangler` for `CLOUDFLARE_API_TOKEN`) without exposing secret values (#594, #604).
Returns `None` for non-Rosen projects.

- **command** `set_project_deploy_secret { project_identifier, name, value }`

Save or replace a named deploy secret in Windows Credential Manager under `velocity/deploy/<project>/<NAME>` and return the updated deploy settings without exposing any secret value (#594).

- **command** `clear_project_deploy_secret { project_identifier, name }`

Remove a named deploy secret from Windows Credential Manager under `velocity/deploy/<project>/<NAME>` and return the updated deploy settings (#594).

- **command** `catch_up_from_mirror { project_identifier }`

Catch the project's Rosen base up to its mirror tip, report the outcome as a toast, and save a divergence for the mirror notice (#501).

- **command** `adopt_mirror_tip { project_identifier }`

Adopt the mirror tip of the project's saved divergence as Rosen #396 does, clear the divergence, and return Rosen's refusal when the tip moved or its edits are not in Rosen.

- **command** `get_project_health { project_identifier }`

Return the project's active health signals, the automatic action taken or block reason, when it acted, and persisted project health history (including idle-slot spells and their durations) (#509, #616).

- **command** `act_on_dispatch_idle_issue { project_identifier, repository, issue_number, action }`

Run a one-click owner unblock action on a blocked issue from the 30-minute dispatch-idle alert: `retry_attempt` (clear the stored attempt record), `mark_needs_owner` (relabel with `needs-owner`), or `lift_hold` (release the person hold), then refresh and return `ProjectHealthView` (#616).

- **command** `resolve_project_host_change { project_identifier, switch_back }`

Switch a project back to its previous issue host or base CI source in one click after a non-owner change, or acknowledge the current setting and clear the project health warning (#613).

- **command** `copy_github_issue_to_collapse { project_identifier, issue_number }`

Re-run Collapse's idempotent GitHub issue import so a missing host issue (`404`) reaches Collapse with its GitHub number, clear the missing-issue health alert, and retry pending land comments, closes or reverts (#614).

- **command** `dismiss_host_issue_problem { project_identifier, issue_number }`

Clear a missing or mismatched host-issue health alert and drop stuck pending updates for that issue number (#614).

- **event** `project://health`

Published when a project's health notifications change (#509).
