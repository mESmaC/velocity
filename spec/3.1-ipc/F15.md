- **command**
  - `list_providers`,
  - `provider_sign_in { provider }`,
  - `provider_sign_out { provider }`,
  - `edit_provider_account { provider, action }`,
  - `install_provider { provider }`,
  - `set_provider_settings { edit }`

Settings → Providers (F15), drawn in Rust.
At startup and after each sign-in the backend starts each provider's ACP agent with no prompt: `initialize` gives its sign-in methods, `session/new` succeeds when its login holds (`auth_required` when it doesn't), and its model option lists the models; each model is selected once to read whether it offers a fast mode.
The answers are saved in `state.json` as the provider catalog, so pickers are right before the agents answer again.
Sign in runs the agent's own login: ACP `authenticate`, or a terminal method's command with no console window; methods that take an API key or bill an API account are never chosen.
Sign out is recorded by Velocity and leaves the CLI login alone.
`edit_provider_account` starts OAuth in a new isolated profile, retries or cancels its sign-in, renames or signs out an account, or sets it as the provider’s default.
Account IDs are scoped by provider and zero denotes its existing CLI login.
`get_model_menu` lists the provider’s accounts and their usage meters.
The `Account` variant of `choose_model` selects an account for the composer or for a thread with no active session.
The thread view reports the account currently assigned to its session.
`install_provider` runs a built-in provider's fixed install steps (F15 Install) for an agent that isn't installed; `provider_sign_out` cancels it while it runs.
`set_provider_settings` shows or hides a model chip, sets the optional per-provider concurrency cap, sets the default model, effort and speed for new threads and the thread title model, and updates the environment variable names allowed to pass through the agent credential filter (#530).

- **command**
  - `set_provider_command { provider, command }`,
  - `add_custom_agent { name, command }`,
  - `remove_custom_agent { provider }`

ACP agent commands in Settings → Providers (F15).
A provider is `claude`, `codex`, `antigravity`, `kimi` or `custom-<id>` for an agent you added.
`set_provider_command` takes the program and its arguments as one line (double quotes around a word with spaces, backslashes kept as typed); `null` resets a built-in provider to its built-in command.
Add an ACP agent takes a name (not one already in use) and a command, with no environment or key field, and saves it in `state.json`.
Removing an added agent drops what was read from it; its threads keep their records, new work can't start on it, and a default or title model on it returns to the built-in default.
Each change asks the agent again over ACP with its new command; running agents keep the command they started with.
An added agent is offered the known bypass modes (`bypassPermissions`, `agent-full-access`, `full-access`, `yolo`) and has no limit source.
Codex selects `agent-full-access` (current codex-acp) or `full-access` (older builds), and starts with `INITIAL_AGENT_MODE=agent-full-access`, because codex-acp otherwise opens every session in its sandboxed `agent` mode whatever your Codex config says.

- **command**
  - `get_token_usage { period, project_identifier?, thread_identifier? }`

Returns ranked thread totals, project totals and role totals with estimated input by source for Today or Week.
When both identifiers are present, returns the selected thread's lifetime totals and role breakdown.
The usage modal response includes the lifetime context hand-off comparison when the trial is enabled or has threshold observations (#467).

- **command**
  - `get_process_memory`

Returns the current Velocity process IDs, roles, memory readings and budgets in MiB for the Usage modal (#481).

- **event**
  - `provider://status`

Settings → Providers whenever a provider's sign-in state, models or limit changes.
Limits are read per account every five minutes and updated from live Claude and Codex reports tagged with the account used for the turn.
The footer meter and the home model pill update on `layout://state`.
