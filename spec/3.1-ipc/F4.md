- **command**
  - `list_threads`,
  - `start_thread`,
  - `send_message`,
  - `delete_thread`

threads.
`start_thread` and `send_message` are the composer's `StartPrompt` and `SteerThread` intents from `dispatch_layout`; `RemoveQueuedMessage { identifier, index }` withdraws a queued message the agent has not read (F4): the backend checks the launch gate afresh, records a `working` thread, creates its workspace on `vel/<slug>` (the message slug until thread titles land), starts the provider's ACP agent there and streams its transcript into `layout://state`.
Messages to a busy agent are queued (Rule 1).
`dispatch_layout` returns as soon as the reducer has cleared the composer and added the message to the thread, live transcript included; the message is then handed to the agent on one background thread, in the order sent and to the project it was written in (withdrawing a queued message goes through the same queue, so it never overtakes the send that put the message there), and a send that never reaches the agent goes back to the composer with a toast saying why (#318).
Every command that takes a lock or does I/O runs off the window's UI thread (#286).

- **command**
  - `get_model_menu { project_identifier, thread_identifier? }`,
  - `choose_model { project_identifier, thread_identifier?, choice }`

The composer's model menu (F4), drawn in Rust: signed-in providers with their models and limit, signed-out ones as "Sign in with …", effort and speed.
On the home composer a pick changes the defaults.
On a thread it is saved on the thread and sent to a live session as `session/set_config_option`, which applies from its next turn and never cancels the running one.
A running thread stays on its provider's agent, so other providers' models are listed but not selectable there.
