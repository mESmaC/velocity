- **command**
  - `get_work_pool { project_identifier }`

F16 read-only work inventory: open tasks, open GitHub issues and unfinished spec entries, with saved thread owners and separate available counts.
For Rosen projects, `rosen_items` carries tracked task and issue status, timestamps, and thread and change links, including completed rows that have left the available pool.
Rosen Work progress publishes `layout://state` so consumers can refresh the saved projection through `get_work_pool` without a Rosen change lookup.
The native adapter reads sources off the UI thread; source errors fail the snapshot.

<!-- split-spec IPC row -->
- **command**
  - `get_goal_swarm_dialog { query }`,
  - `read_goal_swarm_pool { sources }`

Goal swarm dialog (F16).
`get_goal_swarm_dialog` draws the dialog in Rust from the user's choices with one edit applied: the agent count (1–30), the mix rows with "the rest", the split bar, the nick preview, one limits line per provider, the source switches, and the pool line.
The query carries an optional `into` swarm identifier so + Agents draws that swarm's saved sources.
`read_goal_swarm_pool` reads only the active project's selected `sources` off the UI thread for the pool line and the capacity check; the dialog shows the previous read meanwhile.

<!-- split-spec IPC row -->
- **command**
  - `launch_goal_swarm { request }`,
  - `add_goal_agents { request }`

Goal swarm launch and `+ Agents` (F16).
Launch requests carry defaulted work `sources` (tasks, issues and sections); the saved choices also govern + Agents and Keep going.
Checks the launch gate afresh, allocates project-scoped `<nick>` slots on the chosen model mix, creates each member's `<nick>` workspace in `choosing work`, asks the chosen agent to evaluate the user prompt against the enabled inventory before atomically claiming its selected piece in AIRC (re-evaluating a refreshed inventory on refusal), names the change for the claimed piece before starting the ACP session, removes untouched workspaces and posts `left` when nothing remains, and spawns the next round after landing when `keep_going` is on.

<!-- split-spec IPC row -->
- **command**
  - `get_goal_swarm_board { swarm_identifier }`

Goal swarm view claims board (F16).
Reads the swarm's enabled work sources off the UI thread, then joins it with saved claims: claimed pieces first with the holder's nick and state (editing, the AIRC dependency wait, `named · <change>`, `reopened · <change>`, failed or closed · claim held), open pieces next, and the pieces this swarm landed last with `landed <change>`.
The rest of the view (header, prompt bubble, segment bar, one card per agent, activity) arrives on `layout://state` as `active_goal_swarm`, with a `board_revision` that changes whenever a claim, named change or land could move the board; the window reads the board again then.
The goal swarm's sidebar row (`goal: true`) nests its agents' threads; `AddGoalAgents` opens the dialog on the swarm's prompt for `add_goal_agents`, and a message from the goal swarm composer is queued to every working or in-review agent.
