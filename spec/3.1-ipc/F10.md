- **command**
  - `get_swarm_dialog { query }`,
  - `launch_swarm { request }`,
  - `add_to_swarm { request }`

Swarm (F10).
`get_swarm_dialog` draws the dialog in Rust from the user's choices: source counts, open items (taken items and draft tasks shown but unselectable), launchable models with the round-robin split, and the footer.
`launch_swarm` checks the launch gate afresh, records the swarm on the project in `state.json`, raises the project's warm pool to the member count, then for each item atomically adds a member thread on `vel/<task-slug>` or `vel/issue-<n>` (a task becomes Now with its thread) and starts its workspace and ACP agent; `add_to_swarm` does the same into an existing swarm.
The request carries the project, source, items, providers, `close_issues` and `into`; a saved swarm's old `rebase_on_merge` option is ignored on load.
Members are ordinary threads: a member's land marks its task done, and Rosen rebases the other members at their step boundaries.
A message from the swarm composer is queued to every working or in-review member.
