#### §3.1 · F1 IPC

<!-- split-spec: {"order":142,"kind":"ipc","indentation":0} -->
<!-- split-spec IPC row -->
- **command**
  - `get_window_state`,
  - `minimize_window`,
  - `toggle_maximize_window`,
  - `close_window`,
  - `window_heartbeat`

Native main-window state and custom title-bar controls.
The main webview sends `window_heartbeat` once a second so Rust can detect a stalled renderer independently of layout requests.

<!-- split-spec: {"order":143,"kind":"ipc","indentation":0} -->
<!-- split-spec IPC row -->
- **command**
  - `log_window_error { source, message }`

Appends an error the window caught to `velocity.log` in the app data folder: a pane that failed to render (each main pane recovers on its own and redraws from the next snapshot), an uncaught exception or an unhandled promise rejection.
Panics and background thread failures go to the same file, which keeps one older copy (`velocity.old.log`) past 1 MB.

<!-- split-spec: {"order":144,"kind":"ipc","indentation":0} -->
<!-- split-spec IPC row -->
- **command**
  - `get_layout_state`,
  - `dispatch_layout { action }`

`Navigation(Board)` shows the Board or leaves it, and `Navigation(Focus)` returns to the selected thread or Home; the snapshot's `board` lists the lanes and cards.
Backend-owned main-window projection, search, palette selection, Alt hints, contextual keyboard dispatch and navigation requests.
Build intents are gated from the persisted active project's spec lock before publication; snapshots carry launch eligibility, rejection notices and draft-task hints.

<!-- split-spec: {"order":179,"kind":"ipc","indentation":0} -->
<!-- split-spec IPC row -->
- **command**
  - `dispatch_layout` with `ToggleSettled`

Toggle the active project's saved Settled group expansion.

<!-- split-spec IPC row -->
- **event**
  - `window://state`

native maximize/restore state, including changes made by the operating system

<!-- split-spec: {"order":183,"kind":"ipc","indentation":0} -->
<!-- split-spec IPC row -->
- **event**
  - `layout://state`,
  - `layout://intent`

ordered main-window snapshots and typed navigation requests for feature owners; no shell commands cross IPC.
Agent output reaches the window at most ten times a second: a streamed burst that changes nothing saved replaces only its thread's live transcript and is published only when that thread is open or its titling pulse changes, and every change in between is coalesced into the next snapshot (#319).

<!-- split-spec: {"order":194,"kind":"ipc","indentation":0} -->
<!-- split-spec IPC row -->
- **command**
  - `get_update_status`,
  - `check_for_update`,
  - `install_update`

Velocity's own updates (F1 Updates): the Updates modal's view; a check now; download, verify, install and restart.
Each returns the modal's view, and failures show in it.

<!-- split-spec: {"order":195,"kind":"ipc","indentation":0} -->
<!-- split-spec IPC row -->
- **event**
  - `update://status`

the Updates modal and the footer button whenever a check, download or install moves on (F1 Updates)

- **command**
  - `get_local_build_status`

The title bar's local-build controls (F1 Title bar, Local build): the restart offers, a status line with its tooltip, and whether a build or restart is under way.
Empty on a copy that has no local build and isn't making one.

- **command**
  - `restart_into_local_build { commit }`

Restarts Velocity into the kept local build of `commit`: saves state, stops the Rosen servers, replaces the running executable and starts it (#512).
Returns the title bar's view; a failure shows in its status line, and a request made while a build or another restart is under way changes nothing.

- **event**
  - `local-build://status`

the title bar's local-build controls whenever a build starts, waits for memory, finishes or fails, or a restart starts or fails (F1 Title bar, Local build)
